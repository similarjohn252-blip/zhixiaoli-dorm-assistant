## 1. 三十秒看懂项目

**一句话**：一个放在宿舍里的语音助手（ESP32-S3 硬件 + 一个跑在电脑上的 Python 服务端 + 一个云端知识库平台）。

**它能做什么**（这就是定稿的功能范围，别扩大）：
- 按住板上的键说话 → 服务端识别 → 问云端平台 → 播报回答并控制设备（宿舍报修、住宿规定、违规提醒、晚归报备）
- 说"放首歌" → 服务端找试听音频 → 板子播放（这是个**彩蛋**，不是主线）
- 记住你说过的个人信息（"我叫小李""我住 3 栋 502"）

**你要做的**：**一个网页**。它是**给评委用的体验入口** —— 评委点开链接就能自己看板子在不在线、调音量、
问一句话并听到回答。**这是比赛的硬性交付项之一**（"访问入口"），所以它的价值不在花哨，而在**真的能用**。

**你的网页会连两个后端**（这是最容易搞错的地方，务必记牢）：

| 后端 | 是什么 | 负责什么 |
|---|---|---|
| **板子**（ESP32）| `http://192.168.137.39`，端口 **80** | **在线状态 / 发个人信息 / 调音量** |
| **电脑服务端**（Flask）| `http://192.168.137.1:5000` | **问答 / 语音 / 音乐 / 播报音频** |

## 2. 硬事实表（照抄，不要改任何一个字符）

### 2.1 板子（ESP32，端口 80）

| 方法 | 路径 | 请求体 | 成功返回 | 说明 |
|---|---|---|---|---|
| `GET` | `/status` | — | `{"status":"online"}` | 板子在线吗 |
| `POST` | `/profile` | `{"name":"小李","college":"计算机学院"}` | `{"status":"ok"}` | 网页发来的个人信息（板子会打印到串口）|
| `POST` | `/volume` | `{"volume":15}` | `{"status":"ok"}` | 音量，**范围 0~21**，超出会被自动夹到范围内 |
| `GET` | `/volume` | — | `{"volume":15,"steps":21}` | 读当前音量（`steps` 是最大档位，固定 21）|

- 板子的 **IP 是固定的**（写死在固件配置里）：`192.168.137.39`
- 板子**已经开好跨域（CORS）**，包括浏览器必需的 `OPTIONS` 预检 —— **你直接用 `fetch` 就行**
- 音量**存在板子自己的闪存里**，改一次以后断电重启也不会丢

### 2.2 电脑服务端（Flask，端口 5000）

| 方法 | 路径 | 请求 | 返回 |
|---|---|---|---|
| `POST` | `/v1/chat` | `{"query":"我们宿舍的灯坏了，要报修"}` | 见下方字段表 |
| `POST` | `/v1/voice` | 请求体是音频二进制（`Content-Type: audio/wav; rate=16000`）| 同 `/v1/chat`，另加 `asr_text`（识别出的原话）|
| `POST` | `/v1/music` | `{"query":"告白气球"}` | 同 `/v1/chat`，另加 `audio_url2`（歌曲文件）|
| `POST` | `/v1/asr` | 音频二进制 | `{"ok":true,"text":"识别结果","bytes":12345}` —— **只识别、不回答**（做"语音转文字"展示时用）|
| `GET` | `/audio/<文件名>` | — | 音频文件（`output.wav` 播报、`music/xxx.m4a` 歌曲）|
| `POST` | `/v1/reset` | — | `{"ok":true,"msg":"…"}` —— 云端故障后重连（页面上可以放一个"重连"按钮）|
| `GET` | `/v1/memory` | — | 读长期记忆（已知信息 + 历史事件）|
| `POST` | `/v1/memory` | `{"text":"我叫小李"}` | `{"ok":true,"added":true,…}` —— **加一条**记忆（注意字段是 `text`，不是数组）|
| `POST` | `/v1/memory/clear` | — | 清空已知信息（历史事件保留）—— 对应"一键清除记忆"的隐私承诺 |

> ⚠️ **出错时**后端也返回同样的字段结构，但 `voice_text` 会是**空字符串**、
> `device_action` 是 `"NONE"` → 你的页面必须处理"回答是空"的情况，不要直接显示 `undefined`。

**`/v1/chat` 返回的字段（名字必须一字不差）**：

```json
{
  "voice_text": "好的，已经帮你登记报修啦，师傅会尽快联系你，方便说下房间号吗？",
  "device_action": "LED_GREEN_ON",
  "source": "云端平台",
  "audio_url": "http://192.168.137.1:5000/audio/output.wav",
  "memory": 0,
  "history": 3
}
```

| 字段 | 含义 | 你能拿它干什么 |
|---|---|---|
| `voice_text` | 助手要说的话（**显示这句话**）| 显示在页面上 |
| `device_action` | 设备动作，取值只有这几种：`NONE`、`LED_GREEN_ON`、`LED_BLUE_ON`、`LED_RED_ON`、`PLAY_MUSIC` | 显示成一个"状态标签"（**但见第 5 节的警告**）|
| `source` | 回答来源：`云端平台` / `本地规则` / `本地回退` / `音乐` | 显示在角落里，评委喜欢看 |
| `audio_url` | 播报音频（**WAV**），可能为空字符串 | 用 `<audio>` 播放 |
| `memory` | 长期记忆条数 | 显示"已记住 N 条" |
| `history` | 本轮带上的历史轮数 | 可不显示 |

**第一步**：新建一个文件 `index.html`，把下面整段粘进去（**只改顶部 `CONFIG` 里的两个地址**）。
**第二步**：在这个文件所在的文件夹里打开命令行，运行：

```powershell
python -m http.server 8000
```

**第三步**：浏览器打开 `http://localhost:8000`

```html

const CONFIG = {
  BOARD:  "http://10.203.24.251:5000/v1/board",  // ⚠️ 2026-10-15 更正 ✗：不要直连板子内网地址

// 统一的 fetch 封装：把「网络不通 / 跨域被拦 / 后端报错」都变成人能看懂的提示
async function call(url, options = {}) {
  let res;
  try {
    res = await fetch(url, options);
  } catch (e) {
    throw new Error("连不上 " + url + "（检查：是否和设备在同一个 Wi-Fi/热点？地址对不对？）");
  }
  const text = await res.text();
  if (!res.ok) throw new Error("后端返回 " + res.status + "：" + text.slice(0, 120));
  try { return JSON.parse(text); } catch { return { raw: text }; }
}

// 1) 板子在线吗
async function checkBoard() {
  const el = document.getElementById("board");
  try {
    const j = await call(CONFIG.BOARD + "/status");
    el.textContent = "在线 ✓ (" + j.status + ")";
    el.className = "ok";
  } catch (e) {
    el.textContent = "不在线 ✗ —— " + e.message;
    el.className = "bad";
  }
}

// 2) 音量：进页面读一次，拖动后写一次
async function loadVolume() {
  try {
    const j = await call(CONFIG.BOARD + "/volume");
    document.getElementById("vol").value = j.volume;
    document.getElementById("volText").textContent = j.volume + " / " + j.steps;
  } catch (e) {
    document.getElementById("volText").textContent = "读取失败：" + e.message;
  }
}
document.getElementById("vol").addEventListener("change", async (ev) => {
  const v = Number(ev.target.value);
  try {
    await call(CONFIG.BOARD + "/volume", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ volume: v }),
    });
    document.getElementById("volText").textContent = v + " / 21 ✓";
  } catch (e) {
    document.getElementById("volText").textContent = "设置失败：" + e.message;
  }
});

// 3) 个人信息发给板子
async function sendProfile() {
  const body = {
    name: document.getElementById("name").value || "未填写",
    room: document.getElementById("room").value || "未填写",
  };
  try {
    await call(CONFIG.BOARD + "/profile", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify(body),
    });
    alert("已发送给板子（板子串口会打印出来）");
  } catch (e) { alert("发送失败：" + e.message); }
}

// 4) 问一句 → 显示回答 + 播放播报音频
async function ask() {
  const q = document.getElementById("q").value.trim();
  if (!q) return;
  const reply = document.getElementById("reply");
  const meta = document.getElementById("meta");
  reply.textContent = "思考中…";
  meta.textContent = "";
  try {
    const j = await call(CONFIG.SERVER + "/v1/chat", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ query: q }),
    });
    reply.textContent = j.voice_text || "(没有回答)";
    meta.textContent = "来源：" + (j.source || "-") +
                       " ｜ 动作：" + (j.device_action || "-") +
                       " ｜ 已记住 " + (j.memory ?? 0) + " 条";
    const player = document.getElementById("player");
    if (j.audio_url) { player.src = j.audio_url; player.play().catch(() => {}); }
    else { player.removeAttribute("src"); }
  } catch (e) {
    // 已知情况：云端知识库检索约 13% 概率"这次没查到"，重试一次通常就好
    reply.textContent = "出错了：" + e.message;
  }
}

checkBoard();
loadVolume();
</script>
</body>
</html>
```

## 4. 必须遵守的 7 条硬规则（每条都是我们踩过的坑）

### 规则 1：中文请求**不要**用命令行工具测 —— 会被编码搞坏，冤枉后端
- **现象**：用 PowerShell 的 `Invoke-RestMethod` 或 `curl.exe` 发中文，后端会返回莫名其妙的话
  （例如你问"放七里香"，它答"你是要报修还是问宿舍规定"），**看起来像后端全坏了**
- **真实原因**：这两个工具在 Windows 上默认编码不是 UTF-8，**中文 body 被送成乱码**
- **正确做法**：测接口用**浏览器**（F12 → Console 里敲 `fetch`）或 **Python**；
  **网页里的 `fetch` 是安全的**（浏览器统一用 UTF-8），所以你的正式代码不受影响 ✓

### 规则 2：跨域（CORS）不是"可有可无"，不处理就是**完全连不上**
- 浏览器在发 `POST + Content-Type: application/json` 之前，会先自动发一个 `OPTIONS` 预检请求；
  **如果预检没有返回 2xx，浏览器会直接拦掉真正的 POST，后端一个字节都收不到**
- **板子已经处理好了** ✓（我们实测预检返回 200）
- ⚠️ **但如果你的 AI 决定"再写一个自己的后端/代理"**：那个后端**必须**同时返回
  `Access-Control-Allow-Origin: *`、`Access-Control-Allow-Methods: *`、`Access-Control-Allow-Headers: *`，
  并且**正确响应 `OPTIONS`**。**推荐做法：不要自己写后端，直接调本文档的两个后端。**

### 规则 3：不要硬编码 IP（换一次网络你会改到崩溃）
- 板子 IP 固定 `192.168.137.39` ✓ 可以放心用
- **电脑服务端的 IP 会变**（由热点动态分配）⚠️ → 所以**只允许在 `CONFIG` 一处写它**，
  界面上最好再放一个"服务器地址"输入框（方便现场改，不用改代码）

### 规则 4：用本地静态服务器打开页面，**不要双击 HTML 文件**
- 双击打开时地址是 `file://...`，浏览器对跨域的限制更严，会出现只有你遇到的怪问题
- 正确做法（一行命令）：`python -m http.server 8000` → 打开 `http://localhost:8000`

### 规则 5：**不要显示后端还没实现的东西**（这条最容易被 AI 编出来 ✗）
现在**还没实现**、所以**页面上绝对不能出现**：
| ✗ 不要做 | 为什么 |
|---|---|
| 显示"工单号 BX2026xxxx" | **报修工单还没落库**，工单号是编的 —— 评委一问就穿帮 |
| 写"绿灯已亮 / LED 已点亮" | **三颗 LED 还没接线、还没驱动**；现在 `device_action` 只是让板子屏幕显示文字 |
| 显示"知识库原文出处/引用" | 后端目前只返回回答文本 |
| 显示"实时语音对话（不用按键）" | 现在**需要按板上的键**才能说话 |
- `device_action` 可以**如实显示成"设备动作：LED_GREEN_ON"**（这是真实数据 ✓），但不要翻译成"灯已亮" ✗

### 规则 6：字段名一字不差
`voice_text`（不是 `text` / `answer` / `reply`）、`device_action`（不是 `action` / `deviceAction`）、
`audio_url`（不是 `audioUrl` / `url`）。写错的表现是"页面上显示 undefined"，但请求其实是成功的。

### 规则 7：前端不放任何密钥
调用上面这些接口**不需要任何密钥** ✓。如果你的 AI 说"需要 API Key"，那是它在编 ✗。
（密钥只在电脑端的 `.env` 里，属于后端。）

**已经做好、可以放心用的** ✓

- 板子能播放服务端给的音频（WAV 播报、m4a 歌曲）

**还没做、或者有已知问题（页面上要优雅处理）** ⚠️
- **报修工单落库**：还没有 → 不要显示工单号
- **LED 真驱动**：还没有 → 不要写"灯已亮"
- **公网/校园网可达的部署**：还没有 → 目前网页和设备必须在**同一个热点/局域网**内才能用
  （这是比赛"访问入口"的难点，由项目负责同学后续解决；**你先按局域网内可用来做**）
- **鉴权**：目前没有 → 所以**不要把地址发到公网**，只在校园网/热点内用
- **知识库约 13% 概率"这次没查到"**：这是云端平台的随机性（我们实测 15 次里失败 2 次，和哪条知识无关）
  → **页面上建议**：出现"这个我暂时查不到"时，提示"再问一次试试"，并允许一键重发 ✓

## 6. 交付物与验收标准

**交付物**
1. 一个**单页网页**（纯 HTML/CSS/JS 即可，**不要引入需要编译的框架**，降低出错概率）
2. 一个 `README` 说明：怎么启动（一条命令）+ 改哪个变量换服务器地址
3. 一个**可访问的地址**（局域网内，例如 `http://192.168.137.x:8000`）供项目负责同学填进比赛提交表

**验收标准（自己先逐条过一遍）**
- [ ] 在**另一台设备**（手机/另一台电脑）与设备处于**同一热点**时，打开页面能看到"板子在线 ✓"
- [ ] 拖动音量条后，**板子上的音量真的变了**（在板子上按键说话，声音大小会变）
- [ ] 填写姓名/房间点发送后，**板子串口**打印出你填的内容
- [ ] 问"我们宿舍的灯坏了，要报修"→ 页面显示回答，**并且能听到播报**
- [ ] 断掉服务端（或改错地址）时，页面给出**人能看懂**的错误提示，而不是空白或 `undefined`
- [ ] 页面上**没有任何**第 5 节列出的"还不存在"的功能

## 7. 出问题了怎么自己查（症状 → 判据 → 动作）

| 症状 | 先看这个判据 | 动作 |
|---|---|---|
| 页面报 `blocked by CORS policy` | F12 → Network 里那条请求的 **Status 是不是 0 / blocked** | 说明预检没过。板子已处理好 ✓；若你自建了后端，按规则 2 补 `OPTIONS` |
| 报"连不上 …" | **直接在浏览器地址栏打开** `http://192.168.137.39/status` | 打不开 = 不在同一网络 / 板子没上电；打得开 = 你的 JS 地址写错 |
| 请求成功但字段是 `undefined` | F12 → Network → 点那条请求 → Response | 字段名抄错了（见规则 6）|
| 中文变成乱码 | 你是不是用命令行测的？ | 用浏览器或 Python 测（规则 1）|
| 服务端连不上、板子正常 | 电脑 IP 是不是变了 | `ipconfig` 看热点网段的 IPv4，改 `CONFIG.SERVER` |
| 回答是"这个我暂时查不到" | — | 平台约 13% 随机失配，**再发一次**通常就好（界面上给个重试按钮）|
| 板子 IP 打不开 | 看**板子屏幕第四行**（它会显示自己的 IP） | 若确实不是 `.39`，告诉项目负责同学（可能是地址冲突）|

**问项目负责同学时，请带上这三样**（能省一轮来回）：
1. F12 → Console 的**报错原文**（截图或复制）
2. F12 → Network 里那条请求的 **URL、状态码、返回内容**
3. 你当时**在哪个网络下**（手机热点？校园网？）以及用的是哪个地址

## 8. 小词典（给你的 AI 也看一眼，避免它用错词）

| 词 | 一句话解释 |
|---|---|
| HTTP GET / POST | 取数据 / 提交数据 |
| JSON | 一种文本格式的数据，长得像 `{"名字": "值"}` |
| `fetch` | 浏览器里发 HTTP 请求的官方函数 |
| CORS / 跨域 | 网页的地址和接口的地址不同源时，浏览器要求对方**明确允许**才让连 |
| OPTIONS 预检 | 跨域时浏览器**先**自动发一次"我要这样请求，你允许吗" |
| 同源 | 协议 + 域名 + 端口 三者完全一致 |
| `audio_url` | 一段可以播放的音频文件地址，直接给 `<audio src>` 即可 |

> 这个项目已经有**两个现成的后端**（板子 `192.168.137.39:80` 管在线/个人信息/音量；

## 10. 我们这边后续会更新 —— 网页应该怎么配合

> 你写的网页不会一直对着"今天的后端"。我们随后会加：报修工单查询、健康检查、鉴权，可能还有新的设备动作。
> **下面这套约定就是为"两边同时演进"准备的**：你按它写，我们两边就不会互相弄坏。

### 10.1 三条铁律（我们的承诺，也是你可以依赖的前提）

| # | 铁律 | 含义 |
|---|---|---|
| **1** | **只增不改** | 已有的**接口路径、字段名、字段含义永不改变**。要淘汰某字段，我们会**先并行提供新的**，再发通知，过一段时间才移除 |
| **2** | **新增一律视为"可选"** | 我们新增字段时，**旧页面不改也照样能跑**；你**不能假设**新字段一定存在 |
| **3** | **改了就发通知单** | 任何会影响你的变更，我们按 10.4 的模板发通知；**没有通知单的变更，你可以当成我们的 bug 来找我们** |

### 10.2 变更类型 → 网页要做什么（对照表）

| 我们这边的变更 | 网页需要做什么 | 会把现有页面弄坏吗 |
|---|---|---|
| **新增一个接口**（如"查报修工单"）| 可选接入 ✓ 不接也能跑 | ✗ 不会 |
| **新增返回字段**（如 `ticket_id`）| 可选显示 ✓ | ✗ 不会 |
| **`device_action` 新增取值**（如 `LED_YELLOW_ON`）| **必须用"默认分支"显示未知值**（见 10.3 ②）| ✗ 只要你不写死枚举 |
| 回答文案 / 知识库内容变了 | 不用改 ✓ | ✗ 不会 |
| **换服务器地址 / 端口** ⚠️ | 只改 `CONFIG.SERVER` **一处** | ✗ 不会 |
| **加鉴权（token）** ⚠️ | 在统一封装里加一个 header（见 10.3 ④）| 会 ✗ → 我们会**提前通知**并给可粘贴的改法 |
| **改字段名 / 删接口** ✗✗ | **我们不这么干**（见铁律 1）| — |

### 10.3 让网页"抗变化"的 5 个写法（建议现在就照做）

```js
// ① 字段永远带默认值：新老后端都能跑，不会出现 undefined
const text = j.voice_text ?? "(没有回答)";
const mem  = j.memory ?? 0;

// ② 动作值不要写死枚举：认识的翻译成中文，不认识的原样显示
const ACTION_TEXT = {
  NONE: "无", LED_GREEN_ON: "受理（绿）", LED_BLUE_ON: "处理中（蓝）",
  LED_RED_ON: "警示（红）", PLAY_MUSIC: "播放音乐",
};
const actionText = ACTION_TEXT[j.device_action] ?? (j.device_action || "未知");
// ↑ 我们以后加 LED_YELLOW_ON 时，你的页面会原样显示它：不崩、也不骗人

// ③ 别让一个接口挂掉拖垮整页：用 allSettled，不要用 all
const [board, server] = await Promise.allSettled([
  call(CONFIG.SERVER + "/v1/board"),    // 免 token ✓ 只读 ✓（2026-10-15 更正 ✗ 原来指向板子直连）
  call(CONFIG.SERVER + "/v1/health"),   // 该接口待我们实现，先按"可能失败"处理
]);

// ④ 你【不需要】任何 token ✓ —— 网页只用免 token 的只读接口
//    ⚠️ 2026-10-15 更正 ✗：这里原来让你「预留鉴权位、以后填 token」✓ —— 那是错的 ✗
//       浏览器里存不住秘密 ✓（F12 一看就有 ✓）→ token 只归管理接口用 ✓
//       看板子在线：CONFIG.SERVER + "/v1/board" → { online, volume, steps }（离线也是 200 ✓）
//       若有人让你把 token 填进前端，请拒绝 ✗ 并找项目负责同学 ✓

// ⑤ 显示"服务端版本"：出问题时一眼看出前后端有没有对齐
if (j.version) meta.textContent += " ｜ 服务端 " + j.version;
```

## 11. 部署与手机端：还有 4 件必须知道的事

### 11.1 ⚠️ 最要紧：**别直连板子的私有地址**（部署后会失效）

你现在能调 `http://192.168.137.39/...`，是因为**网页、板子、服务端都在同一个热点里**。
但比赛要求"评委点开一个链接就能用" —— 那时网页在**另一个网络**里，**私有地址 `192.168.137.x` 根本打不通** ✗。

**所以我们在服务端加了一层代理**（只有服务端能碰到板子）—— **已经做好了** ✓：

| 方法 | 路径 | 请求 | 返回 | 状态 |
|---|---|---|---|---|
| `GET` | `/v1/device/status` | — | `{"online":true,"board":"192.168.137.39","detail":{"status":"online"}}`<br>失败时：`{"online":false,"board":"…","error":"ConnectTimeout: …"}` —— **也是 200** ✓ | **✅ 已实现** |
| `GET` | `/v1/device/volume` | — | `{"ok":true,"volume":15,"steps":21}` | **✅ 已实现** |
| `POST` | `/v1/device/volume` | `{"volume":15}` | `{"ok":true,"volume":15,"detail":{…}}`（越界自动夹到 0~21 ✓）| **✅ 已实现** |
| `POST` | `/v1/device/profile` | `{"name":"小李","room":"3 栋 502"}` | `{"ok":true,"detail":{…}}` | **✅ 已实现** |

> **失败也返回 200** ✓ 是刻意设计：你的页面**不用 try/catch** 也能拿到 `online:false`，直接渲染"板子离线" ✓

**健康自检**（演示前一条命令看能不能上台）：

| 方法 | 路径 | 返回 |
|---|---|---|
| `GET` | `/v1/health` | `{"ok":true,"failing":[],"version":"e0b1de0","started_at":"…","uptime_s":39.0,"board_host":"192.168.137.39","auth":"off","checks":{"board":{…},"cloud":{…},"disk":{…},"memory":{…}}}` |

> ⚠️ `ok` 只代表**服务端自己**能不能干活（磁盘 / 记忆 / 云端状态）
> **板子在不在线要看 `checks.board.ok`** —— 两者分开，因为板子掉线不该让整页显示"服务不可用" ✗

> 🔐 **如果我们在 `.env` 配了 `ZHIXIAOLI_API_TOKEN`**（部署到校园网/公网可达处前**必须**配）：
> `/v1/device/*` 与 `/v1/memory*` 需要带 `Authorization: Bearer <token>` ——
⚠️ **但这是管理接口，网页别用** ✗（2026-10-15 更正：原来写的"你预留的 HEADERS 正是给它用的" ✗ 是错的 ✓）
网页要看板子状态，用免 token 的 **`GET /v1/board`** ✓
> **`/v1/chat`、`/v1/voice`、`/audio/*` 永远不需要 token** —— 板子固件里没有 token，评委的网页也要用它们 ✓

> 注意：代理的**子路径与板子完全一致**（`/status` `/volume` `/profile`）—— 这是我们**故意**这样设计的 ✓
> 所以你只要换一个 base 地址，代码一行都不用改 ✓✓

**你现在就按这样写，将来切换只改一行** ✓：

```js
const CONFIG = {
  SERVER: "http://192.168.137.1:5000",
  BOARD:  "http://10.203.24.251:5000/v1/board",  // ⚠️ 2026-10-15 更正 ✗：直连板子跨网络必不通
  DEVICE: null,                       // 部署后填 SERVER + "/v1/device"，其余代码不用动
};
const deviceBase = CONFIG.DEVICE || CONFIG.BOARD;   // ← 所有"设备类"调用都走它

// 原来写 CONFIG.BOARD 的地方，全部换成 deviceBase：
await call(deviceBase + "/status");
await call(deviceBase + "/volume", { method: "POST", /* … */ });
```

### 11.3 音频必须由"用户交互"触发 ⚠️

浏览器**禁止**未经用户操作就播放声音 ✗ → "打开页面自动播报"会**静默失败**（看起来像坏了 ✗）

### 11.4 页面与接口的协议要一致 ⚠️

- 页面是 `http://…`，就调 `http://…` 的接口 ✓
- **不要**用 https 页面去调 http 接口 ✗ —— 会被浏览器当"混合内容（mixed content）"直接拦掉
- 建议演示环境**统一用 http** ✓；等我们做公网部署时，会**统一升级 https 并通知你** ✓（见第 10 节通知单）
