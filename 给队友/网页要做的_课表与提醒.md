# 网页端要做的：课表上传与提醒

> 这是给网页同事的活。服务端接口还在写，**你可以先照下面的格式做，用假数据自测**，
> 接口好了直接连。
>
> 服务端那边我会保证返回的字段和下面写的一致。

---

## 一、要做四块东西

**第一块：上传区。** 一个按钮，能选 PDF 文件上传。

**第二块：校对清单。** 上传后显示解析结果，能改、能删。这是整件事的关键。

**第三块：设置区。** 三个参数：第 1 周日期、作息时间表、课前提前多少分钟。

**第四块：提醒预览。** 显示未来几天的提醒，让用户看到"它什么时候会响"。

---

## 二、接口约定

### 上传并解析

```
POST /v1/schedule/upload
Content-Type: multipart/form-data
字段名：file

返回 200：
{
  "ok": true,
  "count": 19,
  "items": [
    {
      "id": "t1",
      "weekday": 3,
      "period": 1,
      "name": "线性代数[理工]",
      "venue": "弘远楼B0321",
      "weeks": [4,5,6,7,8,10,11,12,14,15,16,17]
    }
  ],
  "warnings": ["第 3 页的『实践课程』那几行看起来是备注，已经跳过"]
}

失败返回 400，body 里 {"ok": false, "error": "不认识的 PDF 格式"}
```

`weekday` 是 1 到 7，1 是周一。`period` 是起始节次，取 1/3/5/7/9 之一，表示 1-2 节、3-4 节这样。`weeks` 是周次数组，已经帮你把"单双"算好了。

**注意：上传不保存。** 解析完只是把结果给你看一眼，保存是下一步。

### 保存校对后的清单

```
POST /v1/schedule/save
Content-Type: application/json

{
  "week1_monday": "2026-08-31",
  "early_minutes": 20,
  "periods": {
    "1": "08:30", "2": "09:25", "3": "10:30", "4": "11:25", "5": "14:20",
    "6": "15:15", "7": "16:20", "8": "17:15", "9": "19:00", "10": "19:50"
  },
  "items": [ ...和上面 items 一样的结构，但用用户改过的内容... ]
}

返回 200：{"ok": true, "saved": 19}
```

### 读当前课表

```
GET /v1/schedule
返回同上结构（含 week1_monday、early_minutes、periods、items）
```

### 读未来提醒

```
GET /v1/reminders?hours=48

返回 200：
{
  "now": "2026-10-21T23:30:00",
  "items": [
    {
      "id": 7,
      "at": "2026-10-22T08:10:00",
      "say": "20 分钟后你有大学英语3，在弘远楼A0203，08:30 开始",
      "kind": "class"
    }
  ]
}
```

`kind` 是 `class`（课表提醒）或 `alarm`（语音定的闹钟）。

## 三、上传区要注意的

选文件后**立刻上传并显示"解析中"**，因为解析要一两秒，不能没反应。

**只接受 PDF。** 现在只做 PDF，图片和 Excel 先不做，选错格式要提示。

**上传前检查大小**，超过 5MB 就拦下来，提示"太大了"。

---

## 四、校对清单是重点

解析大概九成准。实测那张真实课表漏了一门课、多了两门不存在的课，原因是教务处的表格有合并单元格，解析时列会错位。

所以这一块不能省。要让用户能：

**看见** —— 按星期几分组，每组下面列当天所有课，形如：

```
星期三
  1-2 节  线性代数[理工]      弘远楼B0321   第 4-8, 10-12, 14-17 周
  3-4 节  大学物理学II（2）    弘远楼B0319   第 3-8, 11-12, 14-17 周
  5-6 节  数字电子技术         弘远楼B0212   第 7-8, 10-12, 14-19 周
  9-10节  影像中的生死学       弘远楼D0237   第 6-9 周
```

**改** —— 课名、教室、节次、周次都能点进去改。

**删** —— 每行右边一个删除按钮。多出来的课主要靠这个清掉。

**加** —— 允许手动加一行，漏掉的课靠这个补。

**警告要显示** —— 服务端返回的 `warnings` 要用黄底提示条显示出来，别让用户错过。

---

## 五、设置区

**第 1 周日期** —— 一个日期选择器。默认填 `2026-08-31`，用户可改。这个填错，所有提醒的日期都会错一周。

**作息时间表** —— 十个输入框，每节一个开始时间。默认值：

```
1 08:30   2 09:25   3 10:30   4 11:25   5 14:20
6 15:15   7 16:20   8 17:15   9 19:00  10 19:50
```

**课前提前量** —— 下拉选 10 / 15 / 20 / 30 分钟，默认 20。

改完这三个要能保存。

---

## 六、提醒预览

显示未来 48 小时的提醒，按时间排序：

```
10月22日 周四 08:10   20 分钟后你有大学英语3，在弘远楼A0203
10月22日 周四 10:10   20 分钟后你有大学物理学II（2），在弘远楼B0319
```

这块主要是给用户确认"它真的会提醒我"，也是演示时最有说服力的画面。

---

## 七、验收怎么做

准备一个真实的课表 PDF，然后：

上传后能看到一份清单，课程数大致对得上。

故意删掉一行，保存，再读出来，删掉的那行确实没了。

改一个节次的时间，保存，提醒预览里的时间跟着变。

把第 1 周日期改成错误的值，提醒预览的日期整体偏移一周，改回来再恢复。
