## 五、课表（五个接口）

| 用途 | 接口 | 备注 |
|---|---|---|
| 上传并解析 | `POST /v1/schedule/upload`（multipart，字段 `file`） | **上传不保存**；400 时 `{"ok":false,"error":"…"}` |
| 保存 | `POST /v1/schedule/save` | `{week1_monday, early_minutes, periods, items}` |
| 读课表 | `GET /v1/schedule` | 进页面读一次 |
| 读提醒 | `GET /v1/reminders?hours=48` | 每条带 `in_seconds`，页面用它算「还有多久」 |

上传区：只收 PDF、>5 MB 先拦、选完立刻「解析中」。
校对清单：按星期分组；课名/教室/节次/周次可改；✕ 删行；可加行；`warnings` 黄底条。
设置区：第 1 周周一、十节时间、提前量 10/15/20/30。

## 六、用户档案（队友 10-22 实现，接口已定稿）

```
GET  /v1/profile            ← {ok,count,limit,items:[{text,shown,kind,ts}]}
POST /v1/profile            ← action: add / update / delete / clear
GET  /v1/profile/state      ← {key_set, from_env, setup_allowed, can_setup_here}（不含档案内容）
POST /v1/profile/key        ← {"key":"4321"} 或 {"action":"reset"}（只允许 127.0.0.1 调）
```

- 鉴权头 `X-Profile-Key`；口令只存 `sessionStorage`，关标签页就没
- 第一次只能在服务端那台电脑上设（`can_setup_here`），防同一 WiFi 下别人替你设
- `.env` 里配了 `ZHIXIAOLI_PROFILE_KEY` 时以它为准，网页上不给改
- 列表同时用 `shown`（打码）和 `text`（原文）：默认打码，聚焦才显示原文
- 三条错误码都翻成人话了：`401` 口令不对 / `409` 档案满 / `400` 单条太长

## 八、我在队友这版上改的 4 处

| 问题 | 后果 | 修法 |
|---|---|---|
| 点「保存」时输入框已失焦、值被换回打码版 | **把打码串当新内容存进库**，原文被覆盖（最严重） | 保存前判断 `value === shown` → 提示「没有改动」直接返回 |
| `call()` 抛错不带状态码，`pfLoad` 里 `e.status === 401` 永远不成立 | 口令错了只显示「后端返回 401：{"need_key":true}」 | 错误对象挂 `status` / `body`；401 单独分支，清口令 + 说明去哪重置 |
| 409 档案满 / 400 单条太长 只显示原始 JSON | 用户不知道该删几条、该缩多少字 | 新增 `pfErrText()`，三个错误码翻成人话 |
| `.hint` 没有 `white-space:pre-line` | 校车「上车地点」那段带换行的说明挤成一整段 | `.hint` 加 `pre-line`；另外 `shown` 缺失时回退用 `text`，口令设之前先校验 4~8 位 |
