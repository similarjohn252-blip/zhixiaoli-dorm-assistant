## 二、接口契约（已定稿，服务端不会再改）

```
GET  /v1/profile
     ← {"ok":true,"count":2,"limit":50,"items":[
          {"text":"我大二，计算机专业","shown":"我大二，计算机专业",
           "kind":"profile","ts":"2026-10-22 23:20:00"}]}

POST /v1/profile   body 里用 action 区分
     {"action":"add","text":"…","kind":"profile"|"private"}   ← kind 可省，省了自动判
     {"action":"update","text":"旧内容","new":"新内容"}
     {"action":"delete","text":"要删的内容"}
     {"action":"clear"}
     ← {"ok":true,"count":n} / {"cleared":n}
```

**鉴权**：请求头 `X-Profile-Key`。也认 `?key=`（方便浏览器直接开 URL 试）。

口令来源：`.env` 的 `ZHIXIAOLI_PROFILE_KEY`；没设就每次启动随机生成 6 位，
打印在服务端启动横幅的 `[档案]` 那两行里。

**为什么不用 API token**：网页刻意不持有任何 token ✓
**为什么也不能裸奔**：档案里有学号、手机号、房间号，同一个热点下谁打开网页都能看见 ✗
→ 折中成一个单独的口令，只存在浏览器 sessionStorage 里，关标签页就没。

## 三、几个错误码要照着显示

- `401` + `{"need_key":true}`：口令不对或没填 → 提示去启动横幅看口令
- `400` + `{"error":"一条别超过 60 字…"}`：单条太长
- `409` + `{"full":true}`：档案满了（默认 50 条）→ 提示先删几条
- `400` + `{"error":"action 只能是 add / update / delete / clear"}`

## 四、我实现时做的四个决定（你可以改，但改之前想一下为什么）

**1. 列表默认打码显示**，聚焦输入框才显示原文。
`shown` 是打码版，`text` 是原文。我用 `dataset.raw` 存原文、`onfocus` 换成原文、
`onblur` 没改动就换回打码。这样旁边有人看屏幕也不至于一眼看到学号。

**2. 删除和清空都有二次确认**（`confirm`）。清空是不可逆的，只有它一个一键抹掉的动作。

**3. 每条都带「可用 / 只存」徽标**。这是整个档案功能的核心概念：
`可用` 会用来做个性化回答，`只存` 只留在本机、不写进回答、也不发给学校平台。
颜色上 `可用` 用绿色 `.badge.ok`，`只存` 用默认灰。

**4. 编辑用"输入框常驻 + 保存按钮"**，不是弹窗。
触屏上少一层交互，手机上也不会被键盘顶飞。

## 五、你可以自由改的

样式、文案、布局、交互细节，随便改，接口不用管。

**唯一要守住的**：`action` 的四个取值、`X-Profile-Key` 这个头、
以及列表要同时用 `shown` 和 `text`（只用 `shown` 就没法编辑，只用 `text` 就打不了码）。

## 六、如果基于旧版重做

如果你手上还是 10-19 那版、准备重做整个页面，那我改的这三处会丢。
两种做法：

一是从 `网页_2026-10-22_含课表.html` 起步（里面已经有课表和档案两块）；
二是照第二节的接口契约自己实现一遍，二十行 JS 就够。

⚠️ 提醒一句：**别在旧版上直接覆盖**。覆盖之后 `USE_MOCK` 会变回 `true`、
课表那块会退回示例数据、档案窗口直接消失 —— 而且不会报错，只是功能没了。
