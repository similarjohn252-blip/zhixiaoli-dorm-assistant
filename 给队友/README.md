## 三、⚠️ 每次发送前的三条自查（**发之前跑一遍** ✓）

```
① 不含任何真实密钥 ✓
   —— 直接搜一遍：正式密钥只应出现在 .env / secrets.h（两者都 gitignored ✓）
   —— 或让提交护栏先跑一次 ✓（它现在连 secrets.h 里的 key 也认识 ✓）

② 地址是【最新的】✓
   —— 校园网 IP 会变 ✓（**到 10-19 已经变过 4 次**：10.103.7.74 → 10.203.24.251 → 10.103.51.219 → 10.203.131.33 ✓）
   ⚠️ **不要把地址写死在文档/代码里** ✓ → 以服务端启动时打印的「对外地址」为准 ✓
   ⭐ 或者走热点：`http://192.168.137.1:5000/`（热点开着时**永远不变** ✓✓）
   —— 以负责人当场给的为准 ✓；用 GET /v1/health 自测是否还有效 ✓

③ 网页不持有 token ✗
   —— 若文档里出现"把 token 填进前端"之类的话 ✓ **那是旧写法** ✗
   —— 一律以《网页前端_对接文档》最上面那个"重要更正"块为准 ✓
```

## 五、背景（为什么规矩这么严 ✓）

```
2026-10-15 发生的事：
① 他照我们【旧版】文档，把真实 token 写进了网页 JS ✗ → 经微信转发出来 ✓
② 那份 token 当晚就【轮换了】✓（旧值 401 ✓ 新值 200 ✓）
③ 顺带补掉护栏一个盲区：固件 secrets.h 里的 key 原来不在护栏认知里 ✓
→ 结论：**文档写错，队友就会照着做错** ✗
   所以对外文档里，凡是"要不要放密钥"这类，必须写得清清楚楚 ✓✓
```
