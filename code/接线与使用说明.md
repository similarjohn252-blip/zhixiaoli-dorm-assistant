# ESP32-S3 语音助手（智小理平台）接线与使用说明

一句话：**按住板载 BOOT 说话 → 电脑上的服务端做语音识别 → 交给智小理平台思考 → 合成语音回传 → 板子播放并在 OLED 上显示全过程。**

```
   ┌──────────── ESP32-S3 ────────────┐
   │  INMP441 麦克风 (I2S_NUM_1)      │
   │  MAX98357 功放  (I2S_NUM_0)      │
   │  SSD1306 OLED   (硬件 I2C)       │
   │  BOOT 按键 = 说话键              │
   └───────────────┬──────────────────┘
                   │ Wi-Fi（电脑热点 2.4GHz）
                   ▼
        ┌──────────────────────┐
        │ 电脑 Flask 服务端     │  run.py
        │  /v1/voice           │
        └───┬───────────┬──────┴────────┐
   校园网 │           │ 百度云         │ 外网
          ▼           ▼               ▼
   智小理平台   语音识别(ASR)    音乐搜索+下载
   (Dify 接口)  + 语音合成(TTS)   （iTunes 官方试听，
                                  只在电脑上做；
                                  板子只收局域网地址）
```

## 一、硬件接线表

### 1. MAX98357 功放（喇叭）

| 模块引脚 | 接到 ESP32-S3 | 说明 |
|---|---|---|
| `BCLK` | **IO5** | 固件 `I2S_BCLK` |
| `LRC` / `WS` | **IO6** | 固件 `I2S_LRC` |
| `DIN` | **IO7** | 固件 `I2S_DIN` |
| `VIN` | **5V** | 4Ω3W 喇叭用 5V 更响；3V3 也能响但小声 |
| `GND` | **GND** | |
| `SD` | 悬空 | ⚠️ 接 GND 会**关断静音** |
| `GAIN` | 悬空 | = 9dB |
| 喇叭 `+` / `-` | 4Ω 3W 喇叭 | 接模块的喇叭输出端子 |

### 2. INMP441 麦克风

模块丝印常见为 `SCK WS L/R` + `SD VDD GND` 两排（本项目实际用的模块）。

| 模块引脚 | 接到 ESP32-S3 | 说明 |
|---|---|---|
| `VDD` | **3V3** | ⚠️ 不要接 5V |
| `GND` | **GND** | ⚠️ 必须和 ESP32 共地 |
| `L/R`（SEL） | **GND** | 选左声道，对应固件 `MIC_LR_LEFT 1` |
| `SCK` | **IO15** | 固件 `MIC_SCK` |
| `WS` | **IO16** | 固件 `MIC_WS` |
| `SD`（DOUT） | **IO17** | 固件 `MIC_SD` |

> **最容易接错的两处**：`L/R` 忘了接 GND（声道选择不定）；把 `WS` 接到了 `L/R` 上（两者相邻，而 `L/R` 是接地的）。
> **判定方法**：把 IO15/IO16/IO17 都设成 `INPUT_PULLUP` 读一次，正确接线时三个脚都应读到 **高（悬空/高阻）**；某个脚读到 **低**，说明它被接到了地上 —— 就是接错了。

### 3. SSD1306 OLED（128×64，4 针）

| 模块引脚 | 接到 ESP32-S3 | 说明 |
|---|---|---|
| `GND` | **GND** | |
| `VCC` | **3V3** | |
| `SCL` | **IO47** | 固件 `OLED_SCL` |
| `SDA` | **IO21** | 固件 `OLED_SDA` |

> ⚠️ ESP32-S3 的**默认 I2C 是 IO8/IO9**，而本项目这块板子上这两个脚实测被拉到 3V3，所以固件里显式指定了 IO21/IO47（`U8g2` 硬件 I2C 构造函数传入 clock/data）。**不要用默认 I2C。**

### 4. 说话按键

| 按键 | 位置 | 说明 |
|---|---|---|
| **BOOT** | 板载（GPIO0） | **不需要接线**；按下 = 拉低，固件内部已开上拉 |

> 复位/上电时**不要按着 BOOT**，否则芯片进入下载模式，程序不跑。
> BOOT 太小不好按的话，可以自己在 **IO0 和 GND** 之间接一个大按键。

### 5. 三颗 LED（真实硬件动作，工程债 C2）

| LED | GPIO（固件里可改） | 语义 | 什么时候亮 |
|---|---|---|---|
| 绿 | **IO4** | 已受理 | 报修建单成功；工单完成 |
| 蓝 | **IO12** | 处理中 | 工单状态＝处理中；晚归报备 |
| 红 | **IO13** | 警示 | 违规提醒；工单被驳回 |

**接线**（三颗各一套）：`GPIO --(电阻)--> LED 长脚(阳极) → LED 短脚(阴极) --> GND`
- 电阻：绿/红用 **220Ω**；**蓝灯建议 100Ω**（蓝灯正向压降高，220Ω 会偏暗）
- 三个引脚都在下面「可安全使用」清单里 ✓（避开了 IO33~37 的 OPI PSRAM ✓）
- 换引脚：只改 `.ino` 末尾的三个 `#define LED_*_PIN` ✓，别处不用动

**行为约定**（固件里的 `ledSet()`）：
- `NONE` → **三颗全灭**（这一轮没有硬件动作 ✓）
- `PLAY_MUSIC` → **不动灯**（保留上一状态，避免放歌时灯乱闪 ✓）
- 同一时刻**只亮一颗** ✓

### 6. 千万不要占用的引脚

| 引脚 | 被谁占 |
|---|---|
| IO0 | BOOT 按键 |
| IO5 / IO6 / IO7 | MAX98357 |
| IO15 / IO16 / IO17 | INMP441 |
| IO19 / IO20 | USB D- / D+ |
| IO26 ~ IO32 | 模块内部 Flash |
| **IO33 ~ IO37** | **OPI PSRAM（必须开，见下）** |
| IO43 / IO44 | 串口日志 |
| IO45 / IO46 | 仅输入 + strapping |
| IO8 / IO9 | 本板实测被拉到 3V3，异常 |
| IO38 或 IO48 | 可能是板载 RGB 灯 |

**可安全使用**：IO4、IO10、IO11、IO12、IO13、IO14、IO18、IO21、IO38、IO39、IO40、IO41、IO42、IO47。

### 接口

| 接口 | 用途 |
|---|---|
| `POST /v1/voice` | **ESP32 上传 WAV 录音** → 识别 → 思考 → 合成 → 返回 JSON（含 `audio_url`） |
| `POST /v1/chat` | 纯文字入口（调试用，不用板子也能测） |
| `POST /v1/asr` | 只做语音识别 |
| `POST /v1/reset` | 开新会话（清 `conversation_id` 和**最近对话**，长期记忆保留） |
| `GET/POST /v1/memory` | 查看记忆 / 手动加一条（`{"text": "用户喜欢三楼"}`） |
| `POST /v1/memory/clear` | 清空已知信息（历史事件保留） |
| `POST /v1/music` | 单独测放歌：`{"query": "周杰伦"}` 或 `{"query": "放一首周杰伦的歌"}` |
| `GET /audio/output.wav` | ESP32 拉取要播放的音频 |
| `GET /audio/music/xxx.m4a` | ESP32 拉取下载好的歌曲 |

响应字段：`asr_text`（听到什么）、`voice_text`（要念什么）、`device_action`（硬件指令）、`source`（**云端平台 / 本地回退 / 本地规则 / 音乐**）、`audio_url`、`audio_url2`（放歌时的歌曲本体）、`memory`（已知信息条数）、`history`（本轮带上的上下文轮数）。

### 记忆功能

**为什么要自己做**：平台自带的多轮（`conversation_id`）是坏的（历史一长就 400，见踩坑 10），所以记忆完全由服务端掌管——把记忆**拼进 `query`** 一起发给平台，平台照样能懂上下文，不需要它做任何修改。

| 类型 | 存哪 | 内容 | 作用 |
|---|---|---|---|
| **短期记忆** | 内存（重启即清） | 最近 **3 轮**问答 | "那明天呢？""它呢？"这类追问能接上 |
| **长期记忆** | `code\记忆.json` | 已知信息（最多 20 条）+ 历史事件（最多 200 条） | 关掉再开也记得你是谁、偏好什么 |

发给平台的内容长这样（服务端自动拼）：

```
【已知信息】
- 用户叫小李
- 用户是计算机学院
- 用户住 3 栋 502

【最近对话】
用户: 我们宿舍的灯坏了
助手: 好的，已经帮你登记报修啦

【当前问题】
那明天能来人修吗？
```

**会自动记住的说法**（只认这几种明确句式，问句和普通聊天不会被误记）：

| 你说 | 记成 |
|---|---|
| 我叫小李 / 我的名字是… | 用户叫小李 |
| 我是计算机学院的 / …专业的 | 用户是计算机学院 |
| 记住我住 3 栋 502 | 用户住 3 栋 502 |
| 我的学号是2021001 / 手机号是… | 用户学号是2021001 |
| 记住… / 帮我记住… | 原样记下（以"我"开头的规范性化成"用户…"） |

**记忆文件**（`code\记忆.json`，可直接编辑 / 备份 / 清空）：

```json
{
  "facts": ["用户叫小李", "用户是计算机学院"],
  "events": [{"time": "2026-10-12 18:08:39", "user": "我叫小李", "reply": "好的，小李，我记住啦！"}]
}
```

> 断网走本地规则时记忆依然有效：问"我叫什么"，本地分支会直接念出"已知信息"里的内容。屏幕第四行也会显示 `记忆N`，一眼看出它记住了几条。

### 找资源：放歌

**架构还是电脑做桥**：搜索和下载都在电脑上完成，只把**局域网 HTTP 地址**交给 ESP32。所以板子不用访问外网、不用 TLS，音源随时能换，固件也只需要多认一个 `audio_url2`。

```
你说"放一首周杰伦的歌"
      ↓
电脑：识别 → 判断是放歌 → iTunes 搜到歌曲 → 下载成 语音\music\music_xxx.m4a
      ↓
返回：audio_url  = 播报"好的，给你放…"（百度 TTS）
      audio_url2 = 歌曲本体（局域网地址）
      ↓
板子：先念播报，念完自动接着放歌（固件里 loop() 的"播放结束"分支切换）
```

**能听懂的说法**（两种，覆盖日常口语）：

| 类型 | 例子 | 搜不到时怎么办 |
|---|---|---|
| **明确说法** | `放一首X` `放首歌` `放首X的歌` `来一首X` `我想听X` `播放X` | 回"没找到《X》，换个歌名或歌手再试试？" |
| **宽松说法** | `放X` `听X` `来X` `播X`（很短、不是"放心/放假/放在哪里"这类词） | **交给云端正常回答**，不会瞎回"没找到" |

只说"放首歌"、没给歌名 → 反问"你想听谁的歌？"，不会瞎搜。

> **想要原唱就带上歌手名**：`放周杰伦的告白气球` → 搜到 Jay Chou 原唱；只说 `放告白气球` 可能搜到翻唱。
> 服务端内置了常见中文歌手 → iTunes 英文名对照表（`_ARTIST_ALIAS`：周杰伦=Jay Chou、邓紫棋=G.E.M.、薛之谦=Joker Xue…），
> 搜的时候会自动补上英文名，给结果打分时也优先原唱、扣掉"翻唱/钢琴版/伴奏"。要加歌手就往那张表里加一行。

**音源与限制**（重要，答辩可能被问）：

| 项 | 说明 |
|---|---|
| 音源 | **Apple 官方 30 秒试听接口**（`itunes.apple.com/search`），免费、无需 key |
| 格式 | m4a / AAC —— 已确认音频库能解（`Audio.cpp:757` 有 AACDecoder，`:2778` 有完整 MP4 盒子解析） |
| **时长** | **只有 30 秒**，这是 Apple 试听接口的硬限制，不是完整歌曲 |
| 匹配 | 按相关性取第一条，**可能搜到翻唱**（例如"晴天"搜到启鸣乐队版本）。想更准就说"放周杰伦的晴天" |
| 缓存 | 下载过的歌按关键词缓存到 `语音\music\`，同一首再点不会重复下载 |

**要换音源**（比如想放完整歌曲、或换成有 key 的 Jamendo/Pixabay）：只改服务端两个函数即可，固件完全不用动——`search_music()`（返回 `歌名, 歌手, 试听地址`）和 `download_music()`（下载并返回可播地址）。注意**下载下来的格式必须是音频库能解的**：MP3（MPEG1，44.1kHz）、m4a/AAC、WAV 都行；**16kHz 的 MPEG2 MP3 不行**（就是当初百度 TTS 踩的那个坑）。

**相关环境变量**：`ZHIXIAOLI_MUSIC=0` 关掉放歌；`ZHIXIAOLI_MUSIC_COUNTRY` 指定 iTunes 地区（默认留空，实测带 `cn` 反而搜不到中文歌）。

## 三、烧录固件

- 开发板：**ESP32S3 Dev Module**
- 分区：`app3M_fat9M_16MB`，Flash `16M`，USB Mode `hwcdc`
- **PSRAM：必须选 OPI PSRAM** ⚠️ 音频库 `setPinout()` 强制要求 PSRAM，没开就是 `setPinout() -> 失败`
- Core Debug Level：建议 `无`（调试打印会拖慢播放）
- 需要的库：`ESP32-audioI2S`、`ArduinoJson`、`U8g2`

Arduino IDE 之外的命令行编译参数（与本项目实测一致）：

```
esp32:esp32:esp32s3:UploadSpeed=921600,USBMode=hwcdc,FlashSize=16M,PartitionScheme=app3M_fat9M_16MB,DebugLevel=none,PSRAM=opi
```

固件文件：`code\sketch_oct8a_copy_20261008145732\sketch_oct8a_copy_20261008145732.ino`

## 四、使用步骤

1. **开电脑热点**（2.4GHz，名称/密码要和固件顶部 `ssid` / `password` 一致），并确认电脑**同时**连着校园网
2. **启动服务端**（见第二节），黑窗口不要关
3. **给板子上电**，串口 115200 应看到：

```
setPinout() -> OK
micInit() -> OK   (SCK=IO15 WS=IO16 SD=IO17, L/R 接 GND)
[OLED] I2C 扫描: 0x3C
[OLED] 初始化完成，地址 0x3C
Wi-Fi 连接成功!
本机 IP: 192.168.137.39
```

4. **按一下 BOOT**，对着麦克风说一句话（例：`我们宿舍的灯坏了`），屏幕会依次显示：

```
待机 按 BOOT 说话
   ↓ 按键
录音中 2.3s 峰值4860
   ↓ 说完静音 1.2 秒自动结束
识别中…  峰值4860  73644 字节
   ↓
听到: 我们宿舍的灯坏了。
回复: 好的，已经帮你登记报修啦，师傅会尽快联系你。
云端平台 · 绿灯 · 记忆1
   ↓
播放中 1s/5s   →   待机 按 BOOT 说话
```

同一时刻串口会打印完整过程（`【录音】`、`【上传】`、`【HTTP返回码】`、`【听到】`、`【语音播报内容】`、`【回答来源】`、`【音频】进度`）。

## 五、参数速查

### 固件（`.ino` 顶部）

| 宏 | 当前值 | 说明 |
|---|---|---|
| `MIC_SCK` / `MIC_WS` / `MIC_SD` | 15 / 16 / 17 | 麦克风 I2S 引脚 |
| `MIC_LR_LEFT` | 1 | L/R 接 GND 时=1（左声道）；接 3V3 改 0 |
| `MIC_GAIN` | **2** | 实测 ×4 会削顶（峰值撞满 32768）故降到 2；声音偏小再加大 |
| `MIC_SILENCE_PEAK` | **2200** | 每 100ms 峰值低于它算"没在说话"。实测底噪≈1130、说话≈4900（增益 2 之后） |
| `REC_MAX_SECONDS` | 6 | 单次最长录音 |
| `REC_SILENCE_MS` | 1200 | 说完静音多久自动停 |
| `BUTTON_PIN` | 0 | 板载 BOOT |
| `I2S_BCLK` / `I2S_LRC` / `I2S_DIN` | 5 / 6 / 7 | 功放 I2S |
| `OLED_SCL` / `OLED_SDA` | 47 / 21 | OLED 硬件 I2C |
| 音量 | 默认 **21**（范围 0~21） | 21=0dB 易破音，18≈-4dB，15≈-13dB。**网页可改且存进 NVS，重启不忘**；`DEFAULT_VOLUME` 只用于"从没设置过"的首次启动 |

> **改了麦克风引脚/增益后怎么验**：屏幕第四行和串口都会显示峰值。说话时峰值几百~几千正常；**一直是 0 = 麦克风没接好**；一直录满 6 秒不停 = `MIC_SILENCE_PEAK` 低于现场底噪，往上调。

**数据流**（板子从不直接上外网 —— 所以不用配 TLS、不用代理）：

```
① 板子 --POST /v1/voice（上传录音）--> 电脑 192.168.137.1:5000
② 电脑 --HTTPS--> 智小理平台（对话 + 知识库）+ 百度（识别/合成）+ iTunes（找歌）
③ 电脑把 audio_url 返给板子，板子再 GET /audio/... 下载并播放
④ 网页 --POST /profile、/volume--> 板子 192.168.137.39:80
```

**一行一条验证**（要确认哪段就查哪段）：

```powershell
Invoke-RestMethod http://192.168.137.39/status        # 板子在线？（期望 online）
Invoke-RestMethod http://192.168.137.39/volume        # 当前音量（只读接口）
Invoke-RestMethod -Method Post -Uri http://192.168.137.39/volume -ContentType 'application/json' -Body '{"volume":18}'

Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -notlike '127.*' }
```

**三个最常见的网络坑**：
1. **板子 IP 变** → 已用固定 IP 治本 ✓（或看 **OLED 第四行**，板子自己报 IP）
2. **烧录报 `PermissionError(13)`** → 串口被 Arduino IDE 的**串口监视器**占着，先关掉再烧
3. **热点必须是 2.4GHz** → 5GHz 时板子只会报 `NO_AP_FOUND`

## 六、踩坑清单（都是本项目实际踩过的）

| # | 症状 | 真正原因 | 解决 |
|---|---|---|---|
| 1 | `setPinout() -> 失败`，`PSRAM: found=0` | 没开 PSRAM（音频库强制要求） | 工具 → PSRAM → **OPI PSRAM** |
| 2 | 有进度、但**不出声**，`输入缓冲=0`、`总时长=0` | 百度 TTS 默认回的是 **16kHz MPEG2 MP3**，音频库解析不了它的头 | TTS 必须用 **WAV**（百度 `aue=6`，服务端 `ZHIXIAOLI_TTS_FORMAT=wav`） |
| 3 | HTTP 500 + 返回 HTML，板子报 `InvalidInput` | edge-tts 被 403 / 服务端异常时返回了 HTML | 改成**百度 TTS 为主**，并加全局异常处理，永远返回 JSON |
| 4 | 屏幕一直"识别中…"，服务端响应只有 197 字节 | **Flask 是旧进程**，路由表里没有 `/v1/voice`（404 被包装成 200+error） | **改完服务端代码必须重启 Flask** |
| 5 | 改了代码却"没生效" | Windows 下**两个 Flask 进程同时绑定了 5000**（SO_REUSEADDR），老进程抢走请求 | `netstat -ano \| findstr ":5000"` 只留一个 LISTENING |
| 6 | 麦克风峰值恒 0，换了所有引脚排列都无数据 | ① 模块 `L/R` 没接 GND；② **`WS` 接到了 `L/R` 上**（相邻且 `L/R` 接地） | 用"上拉/下拉判定法"：三个信号脚都应是**悬空**；出现"接到 GND"就是接错 |
| 7 | OLED 不亮，或 I2C 扫不到设备 | ESP32-S3 默认 I2C 是 IO8/IO9，**本板这两个脚被拉到 3V3** | 显式用 IO21/IO47（U8g2 硬件 I2C 传 clock/data），别用默认 |
| 8 | 串口刷 `Reason: 201 - NO_AP_FOUND` | 热点没开，或不是 2.4GHz | 热点开成 2.4GHz；此时固件会卡在 Wi-Fi 重连循环里（串口每 5 秒提示） |
| 9 | 屏幕"上传失败" | 按 BOOT 时 Flask 还没起来（重启窗口期） | 固件已加**失败后 1 秒自动重试一次**；先确认黑窗口在跑再按键 |
| 10 | 屏幕"服务端报错"，日志 `HTTP 400 … template:N: function "query" not defined` | **平台侧**多轮 workflow 的 bug（历史变长时触发） | 服务端已**自动降级为单轮**；上下文改由"把记忆拼进 query"自己实现（见第二节"记忆功能"），平台修好后 `POST /v1/reset` 恢复 |
| 11 | 云端一直连不上 | 电脑没连校园网（桥接前提），或热点没共享网络 | 电脑需**同时**在校园网 + 开热点；实在不行 `ZHIXIAOLI_BRAIN=local` 保底演示 |
| 12 | 放歌总是"没找到" | iTunes 搜索带了 `country=cn`（实测中国区搜"周杰伦"返回 0 条） | `ZHIXIAOLI_MUSIC_COUNTRY` 留空（默认），代码里搜不到也会自动去掉地区再搜一次 |
| 13 | 歌曲下好了但板子不播 | m4a 的 `ftyp` 品牌不是 `M4A `/`isom`/`mp42`，音频库直接拒收（`Audio.cpp:2839`） | 代码已内置兜底：下载时发现品牌不对，就地改 4 个字节成 `M4A ` |
| 14 | **同一首歌，有的说法能放有的不能**（"放七里香"没反应，"放一首七里香"可以） | 音乐分支原来只认少量固定说法，"放X"不匹配 → 被当闲聊发给云端，云端只会假装答应 | 已加**宽松说法**（`放X`/`听X`/`来X`/`播X`），并用"不像问句 + 排除放心/放假/放在"兜住误触发；宽松匹配搜不到就交回云端 |
| 15 | 放出来的不是原唱（是女声版/R&B版/钢琴版） | Apple 试听库里中文热歌常常只有翻唱，且原唱歌手名是英文，中文搜词匹配不上 | **带上歌手名**（"放周杰伦的告白气球"）；服务端会用 `_ARTIST_ALIAS` 补英文名并优先原唱 |
| 16 | 云端嘴上说"这就给你放"但没声音 | 请求没被判定成放歌，交给了平台；平台是演示人格，会假装办理 | 见 14；另外黑窗口里 `[音乐]` 那行有没有出现，是判断走没走音乐分支的铁证 |
| 17 | 云端回答突然变敷衍（"我在呢，有什么可以帮你的吗？"），偶尔 500 `workflow build node err,err=(大模型)[]` | **平台侧退化**（直连测试同样如此，与我们的代码无关；怀疑额度或它的模型节点异常） | 等一会儿再试、或问平台管理员；演示可 `set ZHIXIAOLI_BRAIN=local` 用本地规则保底（本轮就自动回退了一次） |
| 18 | 云端回答里出现 `</assistant>`、`<user>`，或把我的"已知信息"念出来 | 记忆注入带换行和 `【】`，被平台当成聊天模板标记；同时又传了 `conversation_id`，两份上下文打架 | 已修：上下文压成**单行**、默认不传 `conversation_id`（`ZHIXIAOLI_CLOUD_MULTITURN=1` 才交回平台）、回复统一过 `_clean_voice()` 清洗 |
| 19 | 平台对**任何**问题都只回一句自我介绍（连"校训是什么"也不查知识库），`device_action` 恒为 `NONE` | **平台提示词里引用用户输入的变量没取到值**：模型收到的输入是字符串 `null`（它的思考里会写 `The user input is "null" - essentially empty`）。常见原因是手打 `{{query}}` 而没用变量选择器插入，或开始节点的变量改名后提示词没跟着改；与早先那个 `template:N: function "query" not defined` 同一根因 | **平台侧**：编辑提示词时用变量选择器插入 `sys.query`（或开始节点的 `query`），确认它是彩色标签而不是纯文本。**服务端侧**已加三道兜底：故障识别（认出"收到 null"就切本地规则，5 分钟自动重试、`POST /v1/reset` 立即重试）、动作兜底（会议室→绿灯，图书馆/闹钟→蓝灯）、学校问题在故障时诚实说明（不编答案） |
| 20 | 知识库**明明有内容、命中测试也搜得到**，但一问学校问题就回"这个我暂时查不到"（预览与 API 都一样） | **分两段，别混为一谈**：<br>**(a) 改造前**（3 个节点：开始→大模型→回复，知识库以**工具**形式挂在「大模型」节点上，`ToolChoice: allowed`）：检索完全没有产出。已排除知识库本身（命中测试正常 ✓）与提示词变量（后来修好 ✓），剩下两种可能都在这条工具式检索路径上——**模型没真的调用该工具**，或**它用了应用默认检索设置（阈值通常 0.5）而实测这些段落只有 0.14~0.47 分，被全部滤掉**。未最终定位，也不再需要定位：这条路已被整体替换。<br>**(b) 改造后**（新增**知识检索节点**）：新节点是空配置，必须配齐两处，缺一不可——① **输入变量**没设（灰字"设置变量值"= 没告诉它拿什么去检索）；② 检索结果**没插进大模型提示词**（工作流里**不会**自动注入，必须自己引用 `知识库 / result`） | **平台侧**：① 知识库节点 **输入变量 = 开始 / query**；② 大模型提示词里加 `# 参考资料` 并**用变量选择器插入** `知识库 / result`（手打无效）；③ 命中设置：阈值 **0.2**、TopK **3~5**、向量/全文权重 **0.3 / 0.7**（与"命中测试"里成功的那套一致——默认阈值 0.5 会把实测只有 0.14~0.47 分的段落全部滤掉）；④ **更新发布**。判据：改完后从 API 问"学生手册里对考试作弊是怎么规定的"能答出手册内容 ✓ **已实测通过**。**服务端侧**无需改动（`inputs.query` 已按应用声明传好，含 200 字截断保护） |

## 七、排查速查表

| 串口 / 屏幕 | 含义 | 先查什么 |
|---|---|---|
| `【HTTP返回码】: -1` / 屏幕"上传失败" | TCP 连不上服务端 | Flask 黑窗口在不在 / 热点 / 防火墙 / 服务端 IP 是否还是 `192.168.137.1` |

| 说话识别总是不准 | 音频削顶或太小 | 调 `MIC_GAIN`（看峰值：撞满 32768 = 太大） |
| 点歌说"没找到" | 搜索关键词或音源问题 | 看黑窗口 `[音乐]` 行；换个说法"放周杰伦的歌"；确认电脑能上外网 |

## 十一、链路追踪（一次请求怎么串起来）

服务端给**每个请求**分配一个 6 位短 id（如 `a1b2c3`），并做三件事：

1. **所有日志行都带它** —— 写在 `语音\链路日志.jsonl`（JSON lines，2MB × 3 滚动切割 ✓）
2. **回写响应头** `X-Request-Id`，响应体里也有 `request_id` 与 `timings`（各段耗时 ✓）
3. **板子串口会打** `【链路ID】: a1b2c3` —— 于是"板子上看到的现象"与"服务端日志"能对上 ✓

**怎么用**（排障就一条命令）：

```powershell
E:\Python\python.exe E:\天翼\tools\链路日志.py            # 最近 10 条链路
E:\Python\python.exe E:\天翼\tools\链路日志.py a1b2c3     # 只看这一次（支持前缀 ✓）
E:\Python\python.exe E:\天翼\tools\链路日志.py --slow     # 按总耗时排序，找最慢的
```

输出长这样（**哪一段慢一眼可见** ✓）：

```
[1aa438] 11:09:51  总耗时 6.135s
    各段: 记忆 0.002s 建单 0.037s 平台 3.271s TTS 2.823s
    问: 我们宿舍的灯坏了，要报修
    答: 好的，已经帮你登记报修啦…（工单号 BX20261015-0001，照明，已受理）
    来源: 云端平台·建单
```

**实测参考值**（判断"慢"有个谱 ✓）：记忆 ≈0s ｜ 建单/查台账 ≈0.03s ｜ **平台 3~6s** ｜ **TTS 1.5~3s**
→ 一次问答**正常 5~9 秒**；远大于这个数就先查**平台**那一段 ✓

**关掉或换位置**：`.env` 里 `ZHIXIAOLI_LOG=0` 关闭；`ZHIXIAOLI_LOG_FILE` 换路径 ✓
