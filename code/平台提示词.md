## 粘贴后必须检查的两件事

**① 最后一行的用户输入必须是"变量标签"，不能是手打的字**

在上面那段里，最后一行是插入用户输入的地方：

- 在 Dify 编辑器里把光标放在 `{{#sys.query#}}` 那一行，**删掉它**，然后按 `/` 或 `{` 唤出变量列表，**点选** `sys.query`（对话型应用）或工作流开始节点的 `query`。
- 插入成功后它会显示成**彩色的变量标签**。如果它显示为灰字纯文本，说明没被识别——**模型收到的用户输入就会是 `null`，于是对任何问题都只会打招呼**（这正是你现在遇到的故障）。
- 如果你原来写的是 `{{query}}` 这种 Jinja 风格，Dify 不认这个写法（Dify 的形式是带 `#` 的 `{{#sys.query#}}`）。最稳的方式永远是**点选插入**，不要手打。
- 顺便确认整段提示词里**只有一处**用户输入，不要重复插入。

**② 别把三个 LED 值写成"用或连起来的一个字符串"**

你原来的写法是 `"LED_GREEN_ON或LED_BLUE_ON或NONE"`，模型有可能**原样照抄**这个字符串，那样板子上的灯就不亮了（服务端只认单个值）。所以这里改成了：**示例里只给单个值 + 上面一张对应表**。

## 相对你原来那版，改了四处

| 改动 | 为什么 |
|---|---|
| **"业务办理"提到优先级第 1 位**（原来"学校信息"第 1） | 挂上知识库后，把事务请求也往知识库方向带，会出现"订会议室却回一段自我介绍"。事务必须先判、命中即停 |
| **学校信息分支明确 `device_action` 一律 NONE** | 你原版没写这条，可能出现"查校训却点亮绿灯" |
| **明确禁止罗列能力清单** | 演示时最忌讳"我是你的助手，可以帮你查校训、订会议室…"这种自我介绍式回复（你之前遇到的正是它） |
| **`device_action` 不给三选一的字符串，改给对应表 + 单个示例** | 防止模型原样照抄"LED_GREEN_ON或LED_BLUE_ON或NONE" |

## 改完之后

1. 在平台上**保存并发布**（Dify 要发布新版本才生效）。
2. 让服务端重新去试平台：`POST http://192.168.137.1:5000/v1/reset`（不等它也行，服务端每 5 分钟会自动重试一次）。
3. 验证：问一句 **"咱们学校的校训是什么"**，如果答出了学生手册里的内容，说明变量已经取到值、知识库也挂上了 ✓
